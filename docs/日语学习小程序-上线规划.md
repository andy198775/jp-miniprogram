# 日语学习小程序（对标「百词斩」）开发 → 上线 全流程规划

> 目标：做一个以"日语每日打卡 + 积分积累 + 同桌社交 PK"为核心的微信小程序，最终**上线并可持续运营**。
> 定位参考：百词斩的"单词记忆 + 打卡闭环 + 社交督促"模型，但把"同桌"社交作为核心留存抓手，先从日语（小语种）切入，后续可扩展到其他语种。
> 适用读者：技术负责人 / 独立开发者 / 小团队。本文按"诊断 → 方案 → 架构 → 合规 → 里程碑 → 上线 → 商业化"的结构组织。

---

## 0. 一句话定位与核心循环

**一句话**：用"每日打卡学日语 + 攒积分 + 同桌互相督促 PK"三件套，把"坚持"这件事游戏化，靠同桌关系把次留/周留做起来。

**核心循环（Core Loop）**

```
  ┌──────────────────────────────────────────────────────────┐
  │  每日打开 → 完成当日学习任务（背词/听音/拼写）            │
  │       ↓ 获得                                            │
  │  学习积分 + 连续天数(streak) + 进度          ←─────────┐  │
  │       ↓                                                  │  │
  │  同桌互动：互相提醒/点赞/排行榜比拼                       │  │
  │       ↓                                                  │  │
  │  PK 对战：答题正确率 & 学习量 1v1 比拼  ──→ 胜负反馈 ─────┘  │
  │       ↓                                                  │  │
  │  积分商城兑换皮肤/道具/勋章（虚拟）                       │  │
  │       ↓                                                  │  │
  │  第二天"再打开"的动力（怕断 streak、怕输给同桌）─────────┘  │
  └──────────────────────────────────────────────────────────┘
```

设计要点：**streak（连续天数）+ 同桌关系**是两条最强留存线；积分是通用货币，连接"学习行为 → 社交资本 → 虚拟奖励"。

## 1. 产品方案

### 1.1 目标用户与痛点
| 维度 | 说明 |
|------|------|
| 核心用户 | 日语零基础~N4 的成人自学者（学生/职场人），想"每天学一点但容易放弃" |
| 核心痛点 | 没人督促、容易断更、背了就忘、单机学习没反馈 |
| 我们的解药 | 打卡 streak + 同桌绑定 + PK 输赢 = 外部约束力 |
| 差异化 | 把"同桌"做成长期绑定关系（不是一次性对战），强调"互相不拖后腿" |

### 1.2 功能清单（按 MVP → 完整）
| 模块 | MVP(必须) | 完整版(迭代) |
|------|-----------|--------------|
| 学习 | 每日词包、选义/听音/拼写三种题型、艾宾浩斯复习 | 例句听力、假名书写、能力考真题、错词本 |
| 打卡 | 每日打卡、连续天数、学习积分 | 打卡日历、补卡卡、城市/全国榜 |
| 同桌 | 邀请/匹配同桌、同桌学习榜、互点赞 | 同桌任务、断更提醒推送、同桌等级 |
| PK | 异步答题 PK（比正确率/速度） | 实时 1v1、房间赛、班级赛 |
| 激励 | 积分、等级、勋章 | 积分商城、会员订阅、限定皮肤 |

### 1.3 积分与经济系统（建议值，MVP 可先跑通）
- 背 1 词 = 2 分；完成每日任务 = 10 分；连续第 N 天额外 +N 分；PK 胜 = 20 分。
- 等级：每 500 分升 1 级；勋章：7 天/30 天/100 天连续打卡等。
- 防刷：单日积分封顶、同词重复不计分、后台校验行为日志。

## 2. 功能模块详细设计

### 2.1 学习模块（记忆算法是灵魂）
- **词库分级**：N5（约 700 词）→ N4 → N3。MVP 先做 N5，自建或采购正版词库（**注意版权，见 §8**）。
- **记忆算法**：Spaced Repetition（艾宾浩斯 / SM-2 简化版）。每个词记录"熟练度"，决定复习间隔。
- **题型**：① 看词选义 ② 听音选义（需 TTS）③ 看义拼写（假名/罗马音）。零失败设计参考你之前 PvZ 项目思路：点错只提示"再听一次"，契合"怕批评"的低挫折感。
- **每日任务**：固定词量包（如 20 词/天）+ 复习包，完成即打卡。

### 2.2 同桌社交（核心粘性）
- 绑定方式：微信好友邀请（分享卡片）或系统随机匹配。
- 关系面板：同桌今日进度、连续天数对比、谁先断更。
- 互动：互点赞、断更提醒（订阅消息）、同桌专属排行榜。
- 设计原则：把"比较"包装成"一起进步"，避免 Toxic 排行。

### 2.3 PK 对战
- **MVP 做异步 PK**（成本低、体验已够）：双方各自完成一份同难度题包，系统比正确率/用时，出胜负，计入积分与战绩。
- **完整版做实时 1v1**：WebSocket 房间，抢答/限时答题（见 §3.4）。

### 2.4 积分商城 / 激励
- MVP：纯展示（皮肤/勋章占位）。
- 商业化期：虚拟道具（主题皮肤、专属头像框、复习加速卡）。**实物不在平台卖**（规避电商资质，学你 PvZ 项目的"家庭契约"思路：虚拟奖励平台发，实体奖励用户线下自兑）。

## 3. 技术架构

### 3.1 前端
- **推荐**：微信小程序原生（WXML/WXSS/JS 或 TS）。跨端框架（Taro / uni-app）可后续考虑，但 MVP 用原生最稳、审核最顺。
- 注意：小程序**没有 Web Speech API**，发音必须走插件/云 API（见 3.3）。

### 3.2 后端（强烈推荐微信云开发 CloudBase）
- **云函数（SCF）**：登录、学习记录、积分结算、PK 匹配、订阅消息。
- **云数据库（MongoDB 风格文档库）**：用户、词库、学习记录、同桌关系、PK 战绩。
- **云存储**：词库音频、用户头像、皮肤资源。
- 理由：零运维、与微信登录/支付天然打通、个人/小团队最快上线；和你 PvZ 项目规划一致。

### 3.3 日语发音方案（关键选型）
| 方案 | 日语支持 | 说明 |
|------|----------|------|
| 微信同声传译插件 | 主要中英文 | 日语合成**不确定支持**，需实测 |
| 腾讯云 TTS | ✅ 多语种含日语 | 需后端调用，按量计费，音质稳 |
| 微软 Azure / 百度 TTS | ✅ | 音质好，需密钥与配额 |
| **预录原生音频** | ✅ 最佳 | 采购/录制 N5 词音频，体验最好、离线可用、最稳 |

> 建议：MVP 用**预录音频**（采购正版日语词库常附音频）或腾讯云 TTS 兜底；长期做预录以保音质与离线。

### 3.4 实时通信（PK / 提醒）
- 异步 PK：云数据库即可，无需实时。
- 实时 1v1：云函数 + API 网关 WebSocket，或腾讯云 IM + 实时房间。
- 断更提醒：微信**订阅消息**（需用户授权，一次性订阅，合规且不过度打扰）。

### 3.5 数据存储与隐私
- 用户敏感数据最小化；《隐私保护指引》必填；登录走 `wx.login` + `openid`，不强制手机号（MVP）。

## 4. 合规与主体（上线前置，最关键，别最后才看）

### 4.1 主体选择（决定你能不能"上线 + 收费"）
| 主体 | 注册成本 | 微信支付 | 可选类目 | 适合 |
|------|----------|----------|----------|------|
| 个人 | 免费 | ❌ 不能 | 受限，很多教育类目不能选 | 仅自玩/不收费 |
| **个体工商户** | 低（营业执照） | ✅ | 较全 | **推荐：能收费、成本低** |
| 公司 | 较高 | ✅ | 最全 | 团队/融资 |

> 结论（沿用你 PvZ 项目结论）：**要上线并商业化，必须用个体户或公司主体**。个人主体无法开通微信支付，且多数教育/社交类目选不了，等于"做完了也发不出去"。

### 4.2 小程序类目与资质
- 类目建议：**教育 → 在线教育 / 教育信息服务**（以微信当前类目树为准，提交前在 mp 后台核对）。
- 常见所需资质（以你选的类目实时要求为准，务必在开放社区/类目资质页核对）：
  - 《增值电信业务经营许可证》（ICP 证，涉及有偿信息服务）
  - 或《办学许可证》/ 相关教育资质
  - 若含出版性质电子内容，可能需《网络出版服务许可证》
- 社交功能（同桌/PK/评论）触发**内容安全**：用户发布内容必须接 `msgSecCheck` / `imgSecCheck` 文本图片审核。

### 4.3 内容安全与审核红线
- 用户生成内容（昵称、头像、留言、PK 发言）必须过审。
- 审核规范：不可诱导分享、不可强制关注公众号、不可虚假打卡、不可"分享才能继续"。
- 词库/例句必须**正版或自研**，避免版权投诉导致下架。

### 4.4 隐私
- 配置《隐私保护指引》，`wx.getPrivacySetting` 弹窗授权；仅收集必要数据。

## 5. 开发里程碑（M0 → M4）

| 阶段 | 目标 | 周期(估) | 关键交付 | 验收标准 |
|------|------|----------|----------|----------|
| **M0 立项/资质** | 主体注册、类目确认、词库与发音方案定稿 | 2–3 周 | 个体户执照、小程序账号、词库清单、TTS 选型 | 账号可提交类目、词库≥N5 全覆盖 |
| **M1 MVP 闭环** | 单人可玩：学习+打卡+积分+streak | 4–6 周 | 学习引擎、发音、积分、连续天数 | 单机完成"学→打卡→攒分"闭环 |
| **M2 同桌社交** | 邀请/匹配同桌、同桌榜、互点赞、断更提醒 | 3–4 周 | 同桌关系、订阅消息、排行榜 | 可绑定同桌并收到提醒 |
| **M3 PK 对战** | 异步 PK → 实时 1v1 | 3–5 周 | PK 匹配、战绩、实时房间 | PK 出胜负并计入积分 |
| **M4 商业化** | 积分商城、会员订阅、限定皮肤 | 3–4 周 | 商城、支付、会员 | 可付费、订单可查 |
| **上线准备** | 自测、内容安全、提交审核、灰度、发布 | 2–3 周 | 审核包、隐私指引、运营后台 | 审核通过并正式发布 |

> 总计约 **4–6 个月**（单人/小团队节奏）。可并行压缩：M2/M3 的部分后台可与 M1 同做。

## 6. 上线流程（step by step）

1. **注册账号**：mp.weixin.qq.com 注册小程序（用个体户/公司主体）。
2. **认证**：企业/个体户认证（300 元/年），解锁支付与完整类目。
3. **选类目 + 传资质**：按 §4.2 提交，等类目审核通过（常需补材料，预留时间）。
4. **开发自测**：真机调试、弱网、iOS/Android 双端、内容安全接好。
5. **提交审核**：填功能页截图、类目、隐私指引；避开诱导分享等红线。
6. **审核反馈**：微信常打回"功能不完整/类目不符"，按意见改后重提。
7. **发布 + 灰度**：先 10% 灰度观察崩溃/留存，再全量。
8. **运营迭代**：看留存/次留/同桌绑定率，按数据迭代 PK 与激励。

## 7. 商业化设计（建议节奏：先跑量后收费）

- **MVP 阶段免费**，靠同桌 PK 做自然增长与留存。
- **收费点**：会员订阅（去广告、解锁 N4/N3 词库、高级复习模式）、积分商城虚拟道具。
- **前置条件**：个体户/公司主体 + 微信支付（M0 就必须把主体定了）。
- **不做**：平台直售实物（避电商资质）；"打卡返现"类（涉资金合规风险）。

---

## 8. 风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| 教育类目资质卡审核 | 上不了线 | M0 就定主体+类目，预留补材料时间 |
| 日语 TTS 音质/支持 | 学习体验差 | 预录音频优先，云 TTS 兜底 |
| 同桌冷启动 | 社交无对手 | 先做"系统匹配虚拟同桌/AI 陪练"，再转真社交 |
| 词库版权 | 下架风险 | 自研或采购正版，禁抓百词斩等竞品词库 |
| 留存不及预期 | 商业模式不成立 | streak + 同桌双线驱动，A/B 测提醒文案 |
| 实时 PK 技术复杂度 | 延期 | MVP 用异步 PK，实时版放 M3 |

## 9. 待你确认的关键决策（影响方案走向）

1. **主体**：是否已/愿注册个体户或公司？（决定能否收费与类目）
2. **首版范围**：先做"日语单机 MVP"还是"带同桌的 MVP"一起上？
3. **发音**：接受云 TTS 按量付费，还是愿采购预录音频（一次性成本、体验更好）？
4. **PK 形态**：MVP 先做异步 PK（省事），还是直接冲实时 1v1？
5. **词库来源**：自建有日语基础，还是需我帮忙找正版 N5 词库方案？
